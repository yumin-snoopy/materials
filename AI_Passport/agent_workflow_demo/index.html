同じ依頼、違う「次の一手」

予定外の変化が続く京都旅行。次の行動を誰が決め、結果を見て何を変えたかを比べます。

模式シミュレーションです。 金額・候補・判断・ツールの結果は説明用の架空データです。実際のAI、予約、旅行検索、外部APIは使いません。

両方式への同じ依頼

「週末の京都1泊旅行を、交通・宿泊・食事・観光込みで5万円以内にして」

上限 50,000円
最初の案 46,000円
内訳 交通16,000＋宿18,000＋食事8,000＋観光4,000円

安全条件：予約・決済はしない。5万円を超える案は完成扱いにしない。新しい希望は確認できる案に反映する。

同じ変化を両方に起こす

ワークフロー型も、設計済みの分岐・再試行で対応できます。違いは、登録されていない条件が来たときに「次の行動」を誰が決めるかです。

ワークフロー型に登録された手順
  • 満室 → 代替宿を再検索
  • 雨 → 屋内観光へ変更
  • 遅延 → 登録済みの別経路を検索
  • 予算超過 → 安い宿を再検索し再計算
「歩く距離を短く」は未登録です。
自律型に与えられたもの
  • 目的：希望に合う5万円以内の旅行案
  • 道具：宿・天気・交通・観光・予算の模擬ツール
  • 制約：予約・決済をしない、予算を守る
結果を検証して必要な作業を選び直す想定です。

最終結果と差分

ワークフロー型：人への確認待ち

満室・雨・遅延・予算超過は登録済みの手順で処理し、50,000円の案まで作成。「歩く距離を短く」が未登録なので完成とせず、人に判断と手順の追加を依頼します。

自律型：確認用の案を完成

各ツールの結果を受けて再計画。徒歩を減らすため観光先を駅近くに変え、50,000円の案を提示します。予約・決済はしていません。

差分：同じ変化でも、登録済みの例外では両方式とも対処。未登録の希望では、ワークフロー型は設計変更へエスカレーションし、自律型は道具を選び直して制約内の案を作ります。実際のAIの判断には誤りもあり得るため、案の確認は人が行います。

授業で押さえる点

  1. 各カードの「次の行動を決めたのは」を見る。ツールを使うこと自体は両方式で可能です。
  2. 「結果を受けて変えたこと」を見る。自律型は結果を確認して作業を選び直し、ワークフロー型は登録済みのルールで再試行します。
  3. 未登録の条件への対応は自律型の利点ですが、万能ではありません。権限や安全条件を越える作業には人の確認が必要です。
