本文解説

1. AIエージェントとは

AIエージェントとは、ユーザーの目的を受け取り、 必要な作業を考え、ツールを使いながら、結果を出すAIのことです。

通常のチャットAIは「質問に答える」ことが中心ですが、AIエージェントは 目的達成のために、計画・実行・確認を繰り返す点が重要です。

1
状況把握
目的・条件・現在の状態を読み取る
2
計画
必要な手順や使うツールを決める
3
行動
検索、計算、ファイル作成などを実行する
4
結果評価
結果が目的に合っているか確認し、必要ならやり直す
試験ポイント： AIエージェントの基本サイクルは 状況把握 → 計画 → 行動 → 結果評価。 この4語の順番で覚えます。
身近な例： 「来週の出張を手配して」と頼まれた秘書のように、AIエージェントは 日程を確認し、交通手段を調べ、候補を比較し、予約案を作成します。 ただ文章を返すだけでなく、複数の作業をつないで進めるイメージです。

2. ワークフロー型と自律型

AIエージェントは、すべて同じ動き方をするわけではありません。 ワークフロー型と 自律型に分けて理解します。

まず押さえたい違いは、 「人間が手順を先に決めるか」 「AIが状況を見ながら手順を考えるか」です。

ワークフロー型は、あらかじめ決められた手順に沿って動きます。 一方、自律型は、目的を達成するためにAI自身が作業を分解し、 必要に応じてツールを使いながら進めます。

ワークフロー型

決められた手順どおりに進めるタイプです。 人間が「この順番で処理する」とあらかじめ流れを設計しておき、 AIはその流れに沿って作業します。

たとえるなら、レシピどおりに料理するイメージです。 「材料を切る → 炒める → 味付けする → 盛り付ける」のように、 順番が決まっている作業に向いています。

特徴：安定・確実・管理しやすい

自律型

目的に合わせて、AIが手順を考えながら進めるタイプです。 LLMが状況を判断し、必要なタスクに分け、検索・計算・ファイル作成などの 外部ツールを使いながら処理します。

たとえるなら、旅行プランを任された秘書のようなイメージです。 目的地、予算、日程を見て、交通手段を調べ、ホテル候補を比較し、 必要なら計画を修正します。

特徴：柔軟・複雑な作業に対応しやすい

比較項目 ワークフロー型 自律型
基本イメージ 決められた流れに沿って処理する 目的に合わせてAIが手順を考える
人間の関与 最初に人間が手順を細かく設計する 人間は目的や条件を与え、AIが進め方を考える
向いている業務 受注処理、請求書発行、定型レポート作成、問い合わせの一次対応 市場調査、競合分析、資料作成、複数サイトを調べる調査業務
強み 処理が安定しやすく、ミスや例外を管理しやすい 想定外の状況にも対応しやすく、複雑な依頼に向く
弱み・注意点 想定していない依頼や例外処理に弱い 誤判断、不要な操作、情報漏えいなどを防ぐ管理が必要
覚え方 ワークフロー型＝手順固定型 自律型＝目的達成型

具体例：請求書を処理する場合

ワークフロー型では、 「請求書を受け取る → 金額を読み取る → 上長に確認する → 会計システムに登録する」 という流れをあらかじめ決めておきます。 毎月同じように発生する定型業務に向いています。

自律型では、 「この請求書が妥当か確認して、必要なら過去の取引と比較して」といった依頼に対して、 AIが確認項目を考え、過去データを探し、差異をまとめるような動き方をします。

試験ポイント：
ワークフロー型は「決められた手順に沿う」、 自律型は「目的に合わせてタスクを分解し、ツールを使って進める」と覚えます。 試験では、業務例を見てどちらに近いかを問われる可能性があります。
誤解しやすい点： 自律型のほうが常に優れているわけではありません。 正確性や統制が重要な業務では、ワークフロー型のほうが適している場合があります。 反対に、調査や資料作成のように状況判断が多い業務では、自律型が役立ちます。
補足

ワークフロー型と自律型は、手順を誰が決めるかを比較するための整理です。実際には両者を組み合わせることもあります。AIエージェントにも誤判断はあり、自律型でも権限や実行範囲を決め、人間による確認を組み込みます。

3. 用途別エージェントの特徴

生成AIパスポート試験では、AIエージェントの細かい操作方法よりも、 サービス名と代表的な特徴の対応を押さえることが重要です。 特に、GenSpark、 Manus、 Skywork AI、 MCPは、シラバスの詳細キーワードにも含まれています。

用途別エージェントは、「何でも同じように使うAI」ではなく、 資料作成に強い、 長い作業を任せやすい、 複数の成果物をまとめて作るなど、 目的に応じた得意分野を持っています。

試験対策では、まず 「何をするためのエージェントか」 を一言で説明できるようにしておきましょう。

1 GenSpark

複数の作業をまとめて進めるオールインワン型

GenSparkは、調査、資料作成、表作成、画像生成など、 複数の作業をまとめて進めるタイプのAIエージェントとして理解します。

たとえば「新商品の企画案を作って」と依頼したときに、 情報収集、構成づくり、スライド作成、表の整理などを 一連の流れで支援するイメージです。

覚え方：GenSpark＝「いろいろな仕事をまとめて進める」

2 Manus

複雑な作業を任せる汎用エージェント

Manusは、人間が細かく操作し続けなくても、 複雑な作業を分解して進める汎用的なAIエージェントとして押さえます。

たとえば、複数の資料を読み比べる、条件に合う候補を探す、 評価結果を表にまとめる、といった時間のかかる事務作業に向いています。

覚え方：Manus＝「任せておくと作業を進める」

3 Skywork AI

資料・文書・表などを作るワークスペース型

Skywork AIは、文書、プレゼン資料、表計算、音声コンテンツなどを 同じ作業空間で作成・整理するタイプとして理解します。

たとえば、調査結果をもとにレポートを作り、 その内容をスライドにし、必要な表もまとめるような作業に向いています。

覚え方：Skywork AI＝「資料作成を同じ作業場で進める」

4 MCP

AIと外部ツールをつなぐための共通ルール

MCPは、厳密にはAIエージェントそのものというより、 LLMと外部ツール・データソースをつなぐための仕組みです。

AIがファイルを読む、データベースを検索する、表を作る、業務システムを操作するには、 外部ツールと安全に連携する必要があります。 MCPはそのための共通ルールとして理解するとわかりやすいです。

覚え方：MCP＝「AI版USB-C」

名称 一言でいうと 試験での覚え方
GenSpark 複数のAI機能をまとめて扱うオールインワン型 いろいろな作業をまとめて進める
Manus 複雑なタスクを分解して進める汎用エージェント 任せておくと作業を進める
Skywork AI 文書・資料・表などを作るワークスペース型 資料作成を同じ作業場で進める
MCP LLMと外部ツールをつなぐ共通ルール AIと道具をつなぐ共通ポート

身近な例：文化祭の企画書を作る場合

GenSparkなら、企画案、スライド、表、画像などをまとめて作るイメージです。

Manusなら、過去の資料を調べ、必要な作業を分解し、 企画書完成まで進めていくイメージです。

Skywork AIなら、文書、発表資料、表を同じ作業スペースで整えていくイメージです。

MCPは、それらのAIが外部ツールやデータを使うための接続ルールです。

試験ポイント： サービス名だけを暗記するのではなく、 「GenSpark＝オールインワン」 「Manus＝自律的に作業を進める」 「Skywork AI＝資料作成ワークスペース」 「MCP＝外部ツール連携」 のように、役割とセットで覚えます。
注意： AIサービスの機能名や提供内容は変わることがあります。 試験対策では、最新機能を細かく追いすぎるよりも、 教科書・シラバスに出てくる 「名称」と「代表的な特徴」 の対応を優先して押さえます。
補足

MCPは通信手順をそろえるプロトコル（共通ルール）で、物理的な端子やネットワークのポート番号そのものではありません。「AI版USB-C」は、接続方法を共通化することのたとえです。MCPを使うだけで自動的に安全になるわけではなく、認証・アクセス権限・接続先の確認が必要です。

4. MCPと外部連携

MCPは、 Model Context Protocolの略です。 AIエージェントが外部ツールやデータソースを使うための 共通の接続ルールとして理解します。

通常のLLMは、文章を読んだり作ったりすることは得意ですが、 それだけでは「社内データベースを検索する」「最新の天気を調べる」 「表計算ソフトにデータを書き込む」といった外部の操作はできません。

外部連携の方法の1つがMCPです。APIを直接呼び出すなど、MCP以外の方法でも連携できます。 MCPを使うと、AIが外部ツールとやり取りするための方法をそろえられるため、 AIエージェントがより実用的な作業を進めやすくなります。

たとえ話：MCPは「AI版USB-C」

パソコンにマウス、キーボード、外部ディスプレイ、充電器をつなぐとき、 それぞれの機器ごとにまったく違う専用端子が必要だと大変です。

USB-Cのような共通規格があると、さまざまな機器を同じ考え方で接続できます。 MCPも同じように、AIと外部ツールをつなぐための共通ルールとして働きます。

つまり、「AIが外部の道具を安全に使うための接続口」 と考えるとわかりやすいです。

1. ツール情報取得 AIが「どんなツールを使えるか」を確認する
2. ツール選択 目的に合うツールをLLMが選ぶ
3. ツール実行 必要な入力を作り、外部ツールに処理を依頼する
4. 結果利用 返ってきた結果をもとに回答や次の行動を決める
AIがしたいこと MCPでつなぐ対象 具体例
最新情報を調べたい 検索ツール、ニュースAPI 最新の市場ニュースを取得する
社内情報を確認したい 社内データベース、ファイルサーバー 顧客情報や過去の報告書を参照する
計算や集計をしたい 表計算ツール、分析ツール 売上データを集計して表にする
外部サービスを操作したい メール、カレンダー、業務システム 予定を登録する、メール文案を作る

MCPで押さえる3つの考え方

  1. Tools： AIが実行できる操作です。 例として、検索する、計算する、APIを呼び出す、データベースを調べる、などがあります。
  2. Resources： AIが参照できる情報源です。 例として、ファイル、データベースの内容、社内文書、設定情報などがあります。
  3. Prompts： AIに与える指示テンプレートです。 決まった形式で作業させたいときに役立ちます。
試験ポイント：
MCPはModel Context Protocol。 「LLMやAIエージェントが、外部ツール・データソースと連携するための共通ルール」 と覚えます。
特に、外部ツール連携、 データソース接続、 AI版USB-Cというイメージを押さえましょう。
注意： MCPで外部ツールとつながると、AIができることは増えます。 しかし、社内情報や個人情報にアクセスしたり、外部サービスを操作したりする場合は、 誤操作や情報漏えいのリスクも高まります。 重要な処理では、人間の確認やアクセス権限の管理が必要です。

例：AIが「会議準備」をする場合

ユーザーが「来週の営業会議の準備をして」と依頼したとします。 MCPがあると、AIエージェントは次のような外部連携を行えます。

  1. カレンダーを確認して、会議日時を調べる
  2. 社内フォルダから前回の議事録を探す
  3. 売上データベースから最新の売上を取得する
  4. 表計算ツールで売上表を作る
  5. 資料作成ツールで会議用スライド案を作る

このように、MCPはAIエージェントが 「考えるだけ」から「外部ツールを使って作業する」 ための土台になります。

5. 身近な具体例で理解する

AIエージェントは、単に文章を返すだけではありません。 目的を理解し、作業を分解し、必要なツールを使い、結果を確認する ところまで行うのが特徴です。

ここでは、身近な例を使って 状況把握 → 計画 → 行動 → 結果評価 の流れを確認します。

例1：営業資料を作るAIエージェント

ユーザーが 「新しいサービスを提案する営業資料を作って」 と依頼した場合を考えます。

  1. 状況把握： 顧客の業界、提案するサービス、資料の目的、提出期限を確認する。
  2. 計画： 市場調査、競合比較、顧客課題の整理、スライド構成の作成という作業に分ける。
  3. 行動： Web検索、社内資料の参照、表作成、スライド作成ツールの利用などを行う。
  4. 結果評価： 内容に抜け漏れがないか、顧客に伝わりやすいか、表現が適切かを確認する。

この例では、AIエージェントが 調査・整理・資料作成・確認 という複数の工程をつないで進めています。

例2：旅行計画を立てるAIエージェント

ユーザーが 「2泊3日で京都旅行の計画を立てて」 と依頼した場合です。

  1. 状況把握： 出発地、予算、人数、移動手段、行きたい場所、旅行日程を確認する。
  2. 計画： 交通手段、宿泊先、観光ルート、食事場所を調べる順番を決める。
  3. 行動： 地図、交通情報、宿泊サイト、観光情報などを調べて候補を整理する。
  4. 結果評価： 移動時間に無理がないか、予算内に収まるか、希望に合っているかを確認する。

ただ観光地を列挙するだけなら通常のチャットAIでもできます。 しかし、条件に合わせて調べ直したり、日程全体を調整したりする点が AIエージェントらしい動きです。

例3：問い合わせ対応をするAIエージェント

企業のカスタマーサポートで、 顧客から「注文した商品が届かない」と問い合わせが来た場合です。

  1. 状況把握： 注文番号、顧客名、購入日、配送状況を確認する。
  2. 計画： 注文データベースを確認し、配送会社の情報を調べ、回答文を作る流れを決める。
  3. 行動： 注文管理システムや配送システムを参照し、必要な情報を取得する。
  4. 結果評価： 回答が正確か、顧客に失礼がないか、追加対応が必要かを確認する。

このような業務では、外部システムとの連携が必要になるため、 MCPのような仕組みが重要になります。

例 使う情報・ツール AIエージェントらしい点
営業資料作成 Web検索、社内資料、表計算、スライド作成 調査から資料化まで複数工程を進める
旅行計画 地図、交通情報、宿泊情報、観光情報 条件に合わせて計画を調整する
問い合わせ対応 顧客データベース、注文管理、配送情報 外部システムを参照して回答する
誤解しやすい点： AIエージェントは便利ですが、すべてを完全に任せてよいわけではありません。 特に、予約、送信、購入、削除、社内情報へのアクセスなど、 取り返しがつきにくい操作では人間の確認が必要です。

まとめて覚える一文

AIエージェントとは、 目的を達成するために、状況を把握し、計画を立て、ツールを使って行動し、結果を確認するAI です。

MCPは、そのAIエージェントが外部ツールやデータソースとつながるための 共通の接続ルールです。

まとめ

  • AIエージェントは、目的達成のために状況把握・計画・行動・結果評価を繰り返す。
  • ワークフロー型は決められた業務フローに強く、自律型は複雑な作業を柔軟に進めやすい。
  • GenSpark、Manus、Skywork AIは、用途別エージェントの代表例として特徴を押さえる。
  • MCPは、LLMと外部ツール・データソースを安全・一貫した方法でつなぐ仕組み。
