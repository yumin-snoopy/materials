本文解説

1. プロンプティングの基礎

プロンプティングとは、生成AIに特定のタスクを実行させたり、望ましい応答を得たりするために、入力内容を工夫する技術です。

生成AIに入力する文章や質問そのものを プロンプト と呼びます。プロンプトは、質問形式でも、命令形式でも、要望形式でも構いません。大切なのは「AIが何をすればよいか」を誤解しにくい形で伝えることです。

試験ポイント

プロンプトに特定の決まった形式はありません。 ただし、入力時に4つの要素を意識すると、出力の質が上がりやすくなります。

覚え方

良いプロンプトは「命令 → 前提 → 材料 → 出力形式」

Instruction 何をする？
→
Context どんな前提？
→
Input Data 処理する材料は？
→
Output Indicator どう出す？

プロンプトの4要素

要素 意味 身近な例 試験での押さえ方
Instruction
インストラクション：命令		 AIに何をすべきかを具体的に指示する部分。タスクの内容を明確に伝える。 「次の文章を英語に翻訳して」「誤字を修正して」 何をするかを指定する要素。
Context
コンテキスト：文脈		 AIが適切に回答するための背景情報・参照情報・前提条件。文脈を正しく与えると、回答のズレを減らしやすい。 「あなたはプロのマーケターです」「前回の会議ではA案が採用されました」 背景・立場・前提を与える要素。
Input Data
インプットデータ：入力データ		 AIに処理させる具体的な情報やデータ。AIはこのデータを基に分析・要約・変換を行う。 要約したい長文、アンケート回答、翻訳したい文章 処理対象の材料。
Output Indicator
アウトプットインジケータ：出力指示		 結果をどのような形式・構造・制約で返すかを示す指示。 「5つの箇条書きで」「Yes / Noで答えて」「表形式で」 出力の形を指定する要素。
具体例：悪いプロンプトと良いプロンプト
悪い例：この文章をまとめて。

何をどの程度まとめるのか、誰向けなのか、出力形式が不明です。

良い例：
Instruction次の文章を要約してください。
Context対象は生成AIパスポート試験の初心者です。
Input Data【ここに長文を貼る】
Output Indicator重要語句を太字にし、5つの箇条書きで出力してください。
混同注意
  • Context は「背景・前提」。例：「あなたはプロのマーケターです」
  • Input Data は「処理する材料」。例：「要約したい記事本文」
  • Output Indicator は「出力形式」。例：「表で」「5項目で」「Yes / Noで」
補足

4要素は、依頼を整理するための目安です。毎回すべてを明記したり、この順番や英語の見出しを使ったりする義務はありません。処理対象の本文と指示を見出し・区切り記号で分けると読み違いを減らせます。ただし、区切るだけで誤答や不正な指示への追従を完全に防げるわけではありません。

2. Zero-Shot プロンプティングと Few-Shot プロンプティング

Zero-Shot プロンプティング

Shot（例示） が 0個 の文章構成で入力する方法です。簡単な質問や単純なタスクに向いています。

例：
「次の文章を英語に翻訳してください。
私は明日の会議に参加します。」

Few-Shot プロンプティング

Shot（例示） を 2〜3個 入れてから質問する方法です。望ましい回答パターンをAIに示せます。

例：
入力：商品が届かない → 分類：配送トラブル
入力：サイズが違う → 分類：商品不一致
入力：請求金額が違う → 分類：
比較項目 Zero-Shot Few-Shot
例示 なし 2〜3個程度の例を提示
向いている場面 簡単な質問、一般的な翻訳、短い要約など 分類ルール、出力スタイル、表現のトーンをそろえたい場合
メリット すぐに使える。プロンプトが短い。 回答の形式や判断基準をそろえやすい。
注意点 複雑なタスクでは回答がずれることがある。 例が不適切だと、その誤ったパターンに引きずられる。
試験ポイント

Zero-Shot＝例示なし、Few-Shot＝例示あり。 Few-Shotは「AIを再学習させる」ことではありません。プロンプト内の例を手がかりとして回答させる方法です。

ハルシネーションに注意

AIは、事実と異なる内容や文脈と無関係な内容を、もっともらしく出力することがあります。これを ハルシネーション といいます。

特にZero-Shotで複雑な質問をした場合、信頼性の高い回答と見分けがつきにくいことがあります。最終的には人間が確認する必要があります。

補足

Few-Shotの「2〜3個」は教科書での代表例です。必ず2個か3個に限る定義ではなく、少数の入力・出力例を示す方法です。例を1つ示す方法はOne-Shotと呼ばれます。プロンプト内の例示は通常、モデルの重みを更新する追加学習ではなく、その入力内の手がかりとして使われます。

3. テキスト生成AIのビジネス利用

テキスト生成AIは、文章作成・整理・分析・発想支援など、ビジネスの幅広い場面で利用できます。試験では「どのような用途に使えるか」と「利用時の注意点」が問われやすいです。

文章作成

  • メールの作成
  • キャッチコピーの作成
  • ビジネス書類テンプレート作成
  • 海外企業宛メール文章の作成

調査・分析

  • アンケート項目の作成
  • アンケートの分析
  • タスクの抽出
  • 姓と名の分離

整理・計画

  • アジェンダの作成
  • 業務手順の分解
  • タスクの細分化
  • ふりがなの記載

言語・発想

  • 外国語の翻訳
  • 英単語から英文作成
  • 役割を与えてディベート
  • ブレインストーミング
身近な例

生成AIは「新人に作業を依頼する」ときに似ています。依頼があいまいだとズレますが、目的・前提・材料・出力形式を伝えると、期待に近い成果物になりやすくなります。

利用時の注意点
  • 機密情報・個人情報を安易に入力しない。
  • 翻訳や要約には誤訳・意味の誤解が含まれる可能性がある。
  • 生成文が自然でも、事実確認と人間による最終チェックが必要。
  • 文章からタスクを抽出しても、すべての作業が漏れなく抽出できるとは限らない。
補足

LLM単体の文章生成と、検索・RAG・Python・表計算などの道具を組み合わせたサービスは分けて考えましょう。最新情報の確認や計算、文字数の検査は、道具で補えることがあります。文字数は句読点・空白・改行を含めるかを決め、実際に数えて確かめます。仮説や芸術批評の案は作れても、その正しさや人間の感情体験を保証するものではありません。

4. テキスト生成AIの不得意な作業

生成AIには便利な面が多い一方で、設計原理・学習データ・学習方法に由来する限界があります。試験では「AIに任せてよい作業」と「人間の判断が必要な作業」を区別することが重要です。

不得意な作業 理由・内容 試験での言い換え
新しい情報の生成 AIは既存の知識や学習データをもとに文章を生成するため、新しいアイデアや仮説の提案はできるが、その内容を検証せず、新しい事実として保証することはできない。 「まだ存在しない事実を確実に作る」ことはできない。
感情や直感に基づく判断 AIは人間のような感情や直感を持たないため、直感に基づいた判断はできない。 「なんとなく良い」「感覚的に違う」の判断は苦手。
文脈の深い理解 長文の正確な要約や、複雑な文脈・含意・皮肉を常に正確に捉えることは難しい。 自然な文章でも、細かい意味がずれることがある。
正確な文字数による回答 「100文字で」などの指定に対して、常に厳密な文字数で出力できるとは限らない。教科書ではGPT-3.5の例として、正確な文字数指定が難しいことが示されている。 文字数制限は目安になりやすい。必要なら人間が数える。
複雑な計算 回答が出力されても、計算結果が誤っていることがある。計算は表計算ソフトや電卓などで確認する。 「答えが出た＝正しい」ではない。
最新の情報に関する出力 事前学習を前提とする場合、学習データより後の情報は出力できなかったり、不正確になったりする。検索機能やRAGを用いるサービスは弱点を補えるが、確認は必要。 最新ニュース・価格・法改正は確認が必要。
芸術の批評 AIは独自の思考や感情を持たないため、絵画や音楽などを人間の感性として批評することは難しい。 感性・価値観に関わる評価は人間が行う。
モラルや倫理に関する判断 AIは道徳的な判断や価値観を自分で持っているわけではないため、倫理的な問題の最終判断は難しい。 責任を伴う判断は人間が行う。
試験ポイント

テキスト生成AIは「文章を作る・整える・分類する」ことは得意ですが、事実の保証、正確な計算、最新情報、倫理判断は苦手です。 便利な道具であって、最終責任を負う主体ではありません。

まとめ

  1. プロンプティングは、生成AIから望ましい応答を得るために入力を工夫する技術。
  2. 良いプロンプトは Instruction・Context・Input Data・Output Indicator の4要素で整理できる。
  3. Zero-Shotは例示なし、Few-Shotは2〜3個程度の例示あり。
  4. 生成AIはビジネス文書作成、翻訳、要約、タスク分解、ブレインストーミングなどに活用できる。
  5. ただし、機密情報・個人情報の入力、誤訳、ハルシネーション、計算ミス、最新情報、倫理判断には注意が必要。
最重要：4要素 Zero-Shot＝例なし Few-Shot＝例あり ハルシネーション 人間の確認が必要
